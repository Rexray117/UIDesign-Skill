# UI 文案与语义层的 AI 味

界面上的文字是最快暴露 AI 味的层——用户 3 秒内就能感觉到「这段话说得不像人」。
本节把中文写作去 AI 味的方法论迁移到界面文案（标题、按钮、空状态、错误、引导）。

> **收益最大的改动在这里。** 视觉层改造见效慢且易误杀，文案层改造零风险、立刻见效。
> 因此 `workflow.md` 的 G4 把 D6 排在第一优先级。

---

## 一、四条元原则

| 原则 | 说明 |
|------|------|
| **保真优先** | 只改「怎么说」，不改「说什么」。不新增数字、资质、客户名、承诺 |
| **具体优于漂亮** | 一个具体数字胜过三个形容词 |
| **允许笨拙** | 人类写的界面文案会有口语、省略、不完全对仗。**过度工整 = AI 味** |
| **有立场** | 敢说「不适合谁」，比只说「适合所有人」可信 |

---

## 二、中文空洞词与句式表

### 2.1 高频空洞词（命中即复核）

| 类别 | 空洞词 | 替换方向 |
|------|--------|----------|
| 全景自称 | 一站式、全方位、all-in-one、闭环、赋能、抓手、生态 | 写清具体覆盖了什么 |
| 无信息形容词 | 高效的、智能的、强大的、卓越的、极致的、领先的 | 删，或换成数字 |
| 通用动作 | 助力、赋能、打造、重塑、解锁、开启 | 换成用户实际做的动作 |
| 抽象名词 | 能力、价值、体验、场景、方案、体系（单独出现时） | 换成具体对象 |
| 空洞承诺 | 显著提升、大幅降低、全面提升 | 写百分比或区间 |
| 时效包装 | 全新升级、焕新登场、重磅上线 | 删，直接说变了什么 |
| 通用收尾 | 开启你的旅程、解锁更多可能、让一切变得简单 | 换成具体下一步 |

### 2.2 高危句式

| 句式 | 例子 | 为什么是 AI 味 |
|------|------|---------------|
| **三词排比** | 「快速、安全、可靠」 | 无信息量，任何产品都能写 |
| **不是 A 而是 B** | 「这不是工具，而是伙伴」 | 假靶子——否定没人做过的判断 |
| **假二选一** | 「告别 X，拥抱 Y」 | 空洞对照，无实际信息 |
| **通用积极收尾** | 「让我们一起，开启高效工作新篇章」 | 说了等于没说 |
| **免責式限定堆叠** | 「可能有助于在一定程度上提升」 | 过度限定，读者抓不到重点 |
| **疑问式标题无答案** | 「你的团队还在用 Excel 吗？」 | 若下文不给出具体替代方案即空洞 |
| **过度对仗** | 「更快一步，更省一筹，更稳一方」 | 为了排比牺牲信息 |

### 2.3 标点与符号

| 信号 | 说明 |
|------|------|
| emoji 承担图标职责 | 全站禁用。图标用 SVG 图标族 |
| 破折号密度过高 | 界面文案中每屏破折号 > 1 处需复核 |
| 感叹号堆叠 | 「！」用于营销页可接受；用于企业界面需删 |
| 全大写英文强调 | 界面 chrome 中避免 |

## 三、分位置处方

### 3.1 页面标题 / Hero

| 处方 | 说明 |
|------|------|
| 必须含一个具体名词或数字 | 否则判为空洞 |
| 主标题 ≤ 12 个中文字 | 超过说明没想清楚 |
| 不用双关与文艺腔 | 界面不是散文 |

| ❌ AI 味 | ✅ 有立场 |
|---------|----------|
| 让数据分析变得简单 | 20 万行日志，查出那一条异常 |
| 开启高效协作新时代 | 三个人改同一份文档，不会互相覆盖 |
| 智能赋能业务增长 | 每天 8 点，把昨日 GMV 推到群里 |

### 3.2 按钮 / CTA

| 处方 | 说明 |
|------|------|
| 动词开头，说清结果 | 「创建项目」优于「提交」「确定」 |
| 不用「了解更多」 | 改成具体内容：「看 3 分钟演示」 |
| 主按钮全站措辞统一 | 同一动作不要出现 3 种说法 |

| ❌ AI 味 | ✅ 有立场 |
|---------|----------|
| 立即体验 / 了解更多 / 开始使用 | 免费试用 14 天（不用绑卡）/ 看完整接口文档 |
| 提交 | 保存并发布 |
| 确定 | 删除这 12 条记录 |

### 3.3 空状态

空状态是**最容易被写成 AI 味**的地方（因为最容易套模板）。

| 处方 | 说明 |
|------|------|
| 说清「为什么空」+「怎么填」 | 两句，不多 |
| 主行动按钮必须具体 | 不要「去创建」 |
| 不用插图凑数 | 除非插图真的解释了状态 |

| ❌ AI 味 | ✅ 有立场 |
|---------|----------|
| 暂无数据 🎉 快去创建你的第一条记录吧！ | 还没有巡检记录。点「新建巡检」跑一次，或导入历史 CSV。 |
| 这里空空如也~ | 这个项目下还没有成员。输入邮箱邀请，或从组织通讯录批量添加。 |

### 3.4 错误提示

| 处方 | 说明 |
|------|------|
| 说清「原因 + 怎么修」 | 只写「输入无效」等于没说 |
| 就近显示，不用「操作失败」这类笼统话 | |
| 不指责用户 | 「格式不对」→「手机号需要 11 位」 |

| ❌ AI 味 | ✅ 有立场 |
|---------|----------|
| 操作失败，请稍后重试 | 上传超时（30s）。文件 240MB，超过 100MB 上限，请压缩后重试。 |
| 输入无效 | 结束时间必须晚于开始时间 |

### 3.5 功能描述 / 特性列表

| 处方 | 说明 |
|------|------|
| 「功能 → 用户能得到什么」 | 不要只写功能名 |
| 每条不超过两行 | |
| 至少一条写出边界或代价 | 敢说代价才像人写的 |

| ❌ AI 味 | ✅ 有立场 |
|---------|----------|
| 强大的权限管理 | 按项目分组授权；暂不支持跨组织继承 |
| 智能告警 | 阈值 + 同比双条件触发；误报率 3%，可用白名单压制 |
| 无缝集成 | 已支持 Jenkins / GitLab / 企业微信；Slack 在路线图上 |

### 3.6 引导 / 提示

| 处方 | 说明 |
|------|------|
| 用第二人称，但别滥情 | 「你」可以，「亲爱的用户」不行 |
| 一步一步，一次说一件事 | 不要三步并成一句 |
| 允许口语 | 「这步会慢一点」「不用填也能试」 |

## 四、改写流程（五步）

```
1. 标出全部面向用户的字符串（文案清单）
2. 逐条过 §2 的词表与句式表，标记命中
3. 对命中项执行：删除 → 具体化 → 带入场景
4. 替换测试：把产品名换成竞品名，若仍成立 → 重写
5. 通读检查：全站按钮措辞是否统一；同一概念是否始终同一说法
```

## 五、终检（五问）

| 问题 | 不合格信号 |
|------|-----------|
| 有没有具体数字或名词？ | 通篇形容词 |
| 换到竞品身上还成立吗？ | 成立 = 空洞 |
| 敢不敢说「不适合谁」？ | 只说优点 = 不可信 |
| 按钮说的是结果还是动作名？ | 只说「提交」「确定」 |
| 空状态/错误态说清原因和下一步了吗？ | 只写「暂无数据」「操作失败」 |

---

## 六、红线

- **不新增**原文没有的数字、客户名、资质、承诺、因果关系。
- **不夸大**：不把「可能」写成「一定」，不把相关性写成因果。
- **不虚构**客户证言、案例、数据。
- **不擅自改动**用户明确要求保留的品牌口号、法律文本、专有名词。
- 处理含密钥/凭据的文本时立即停止，请用户脱敏。

## 七、与 `deai-promax` 的关系

本文件是**界面文案场景**的裁剪版。若需要处理的是长文本创作（自媒体 / 小说 / 营销长文），
应改用 `deai-promax` 技能——它包含朱雀检测器五维对抗、五层爆破法、24 种 AI 写作模式与启发式自检脚本，
覆盖范围远超界面文案。

**分工**：
- 界面上的字符串（标题、按钮、空态、错误、提示）→ **本文件**
- 成篇的正文、长文、脚本 → **`deai-promax`**
