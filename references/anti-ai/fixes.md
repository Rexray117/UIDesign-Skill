# 对症改造处方

按 `diagnosis.md` 的诊断结果，对命中的维度逐项改造。
**改造顺序固定**：D6 语义 → D5 结构 → D2 色彩 / D4 排版 → D3 装饰 → D1 布局。
理由：越靠前的层，单位改动收益越大，且改动会连带影响后面的层。

> **动手前必读**：`false-positives.md`。表中每条处方都标了「不适用场景」，请先确认。

---

## D6 · 语义空洞 → 具体化

### 处方

| 编号 | 症状 | 改造动作 | 不适用场景 |
|------|------|----------|-----------|
| D6-1 | emoji 当图标 | 换成同一 SVG 图标族的图标；图标尺寸走 token | 无 |
| D6-2 | 空洞正向词 | 删除，替换为**该产品独有的事实** | 无 |
| D6-3 | 通用积极收尾 | 改为具体下一步动作或一个真实数字 | 无 |
| D6-4 | 无具体值 | 至少补一个数字、时间、范围或具体名词 | 无 |
| D6-5 | 三词排比 | 只留最有信息量的一个，其余删除或展开成证据 | 无 |
| D6-6 | 空洞自称 | 「一站式」→ 写清具体覆盖了什么 | 无 |

### 改造前后对照

| 前（AI 味） | 后（有立场） |
|-------------|-------------|
| `Empower your workflow` | `把 200 台设备的巡检从 4 小时压到 20 分钟` |
| `Seamlessly integrate with your tools` | `已支持 Jenkins、GitLab、企业微信；Slack 在路上` |
| `Your all-in-one solution` | `告警、工单、复盘——一个页面盯完` |
| `🚀 Fast · 🔒 Secure · ⚡ Reliable` | `冷启动 180ms；全链路 TLS；月可用性 99.95%` |
| `Start your journey today` | `用测试数据跑一遍，不用留手机号` |

### 判定法

> **替换测试**：把句子里的产品名换成竞品名，还成立吗？
> 成立 → 空洞，重写。不成立 → 保留。

## D5 · 结构同构 → 内容驱动

### 处方

| 编号 | 症状 | 改造动作 | 不适用场景 |
|------|------|----------|-----------|
| D5-1 | 骨架重复 | 让**内容量决定列数**：条目 3 个用 3 列，条目 7 个用主卡+列表，不要一律三等分 | 严格对称的业务表单 |
| D5-2 | 默认三段式 | 拆掉「标题+副标题+3卡片」，改成：一个主卡 + 一个对照表 + 一行注 | 无 |
| D5-3 | 空/加载态缺失 | 补 empty / loading(skeleton) / error 三态 | 无 |
| D5-4 | 列表与详情同构 | 列表重「比较」（对齐的表格/紧凑列），详情重「阅读」（更大留白、分组卡片） | 无 |
| D5-5 | 层级均质 | 挑出唯一主卡：加大、跨列、换底色或提对比，其余降一档 | 无 |
| D5-6 | 模块失控 | 单屏并列 ≤9；超出的降级为可折叠/次级页 | 监控大屏（可放宽，见场景处方） |

### 执行方法：先内容后骨架

```
1. 列出这一屏必须承载的全部内容项（不要先想布局）
2. 标出「谁最先被看」（唯一答案）
3. 标记内容之间的真实关系：并列 / 主从 / 时序 / 因果
4. 关系决定结构：
   并列 → 网格      主从 → 主卡+次级
   时序 → 纵向流    因果 → 分组+分隔
5. 现在才画骨架
```

**跳过第 1–3 步直接画骨架，就是结构同构的成因。**

## D2 · 色彩惰性 → 有立场的配色

### 处方

| 编号 | 症状 | 改造动作 | 不适用场景 |
|------|------|----------|-----------|
| D2-1 | 色相过多 | 收敛到 **1 主 + 1 强调 + 4 档中性**；其余降为同色相深浅 | 数据可视化（分类色板合法，见 `charts.md`） |
| D2-2 | 紫粉渐变 | 删除，换为单色相深浅或改用材质/深度表达 | 品牌明确要求紫色 |
| D2-3 | 强调色过多 | 一屏只留 1 个强调色；其余强调降为中性 + 加粗/加图标 | 无 |
| D2-4 | 硬编码色值 | 抽为语义 token（`--color-primary` 等） | 无 |
| D2-5 | 装饰性渐变 | 渐变只准用于三种合法用途：**材质 / 深度 / 进度热力** | 无 |
| D2-6 | 中性色缺层次 | 建 4 档中性：主文字 / 次文字 / 三级说明 / 占位禁用 | 无 |

### 色数收敛法

```
第 1 步：列出当前所有唯一色相
第 2 步：挑出「真正承载品牌或语义」的 1 个，定为主色
第 3 步：挑出「唯一需要被注意到」的 1 个场景，定为强调色
第 4 步：其余全部转为主色的深浅变体，或中性灰
第 5 步：功能色（成功/警告/错误/信息）单列，不计入以上，且只用于状态
```

### 关于「有立场」

有立场 ≠ 好看。有立场 = **这个配色换到别的产品上会显得不对**。
- 有立场：`#0F172A` 深海军蓝 + `#22C55E` 数据绿（金融监控）
- 无立场：`#6366F1` 靛蓝 + `#F8FAFC` 浅灰（任何产品都能用 = 谁都不属于）

## D4 · 排版扁平 → 强对比层次

### 处方

| 编号 | 症状 | 改造动作 | 不适用场景 |
|------|------|----------|-----------|
| D4-1 | 字号档数不足 | 建 ≥5 档，且**最大/最小 ≥3.5×** | 无 |
| D4-2 | 标题正文比不足 | 提到 **≥2.0×**，关键处可到 **3–5×** | 企业级密集界面可到 2.0–2.5× |
| D4-3 | 字重单一 | 用 **400 / 500 / 600** 三档做层次（标签用中重、标题用较粗） | Ant Design 式产品可用 400/600 两档 + 字距补偿 |
| D4-4 | 字重极端 | 界面 chrome 禁用 100–300 与 700+ | 长期文档正文可用斜体 |
| D4-5 | 行高均一 | 区分：大标题 1.1–1.25 / 正文 1.5–1.75 / 数据行 1.3 | 无 |
| D4-6 | 缺字距 | 大字号标题收紧字距（负值）；全大写小字放开字距（正值） | 中文标题一般不收紧 |
| D4-7 | 数字未等宽 | 数据列/价格/计时加 `font-variant-numeric: tabular-nums` | 无 |

### 「对比必须敢于强」的执行

层次不是「稍微大一点」，而是**一眼就分得开**：

| 元素 | 字号 | 字距 / 其它 |
|------|------|-------------|
| 关键数字（KPI） | 48–72px | 收紧字距 + `tabular-nums` + 字重 600 |
| 页面主标题 | 28–38px | 收紧字距，行高 1.15 |
| 区块标题 | 18–20px | 正常 |
| 正文 | 14–16px | 行高 1.6 |
| 标签 / 说明 | 12–13px | 可放开字距 |

**最大与最小比 = 48/12 = 4×**。这才是「敢」。

## D3 · 装饰过载 → 克制

### 处方

| 编号 | 症状 | 改造动作 | 不适用场景 |
|------|------|----------|-----------|
| D3-1 | 阴影层级混乱 | 收敛到 **≤3 档**：raised（轻微）/ popup（浮层）/ card（卡片） | 无 |
| D3-2 | 阴影过深 | 模糊半径 > 40px 只允许浮层；静态卡片 ≤ 24px | 无 |
| D3-3 | 圆角值混乱 | 收敛到 **3 档**：控件档 / 表面档 / 胶囊档 | 无 |
| D3-4 | 圆角通用化 | 控件圆角 ≤ 表面圆角；大圆角（≥16px）只用于表面或胶囊 | 品牌调性为「玩具感/亲和」时可用大圆角控件 |
| D3-5 | 装饰性光晕 | 删除装饰性 glow；发光只用于表达「活跃/告警」 | OLED 暗色主题可保留极克制的光 |
| D3-6 | 全员 hover 抬升 | 只让**可点击的卡片**抬升，静态信息卡不响应 | 无 |
| D3-7 | 无留白 | 建立间距尺度，区块间距 ≥ 3× 内部间距 | 密集监控界面（按场景处方放宽） |

### 减法清单（逐项问「删了会损失什么信息？」）

- 渐变背景 → 删（除非表达材质/深度）
- 光晕 → 删
- 装饰性分割线 → 若已有间距区分则删
- 装饰性图标 → 删（图标只在承担语义时保留）
- 第二个强调色 → 删
- 卡片阴影 → 若已有边框或底色区分则删
- 第 3 个动效 → 删

**答不出「损失什么信息」的，一律删。**

## D1 · 对称惯性 → 非对称与节奏

### 处方

| 编号 | 症状 | 改造动作 | 不适用场景 |
|------|------|----------|-----------|
| D1-1 | 居中密度过高 | 正文与列表一律左对齐；居中只留给**真正的对称物**（单一 CTA、数字、空状态） | 营销页 Hero、空状态、单一表单 |
| D1-2 | 等分栅格滥用 | 引入 **1–2 处跨列/不等宽**：主卡跨 2 列、侧栏 1/4 宽 | 数据表格、管理界面表单 |
| D1-3 | 无不对称结构 | 至少建 3 处非对称：跨列、偏移、尺寸对比 | 无 |
| D1-4 | 留白均匀 | 建立**纵向节奏**：分组内 8/12，分组间 32/48，章节间 64/96 | 密集界面按场景缩放 |
| D1-5 | 对称 Hero | 营销页改「左文右图」或「偏置标题 + 出血图」 | 无 |

### 非对称的三种安全做法

1. **跨列**：主元素跨 2 列，次元素各占 1 列 → 天然主次
2. **偏置**：内容区左对齐但整体偏左或偏右，留出大块负空间
3. **尺寸对比**：同一行内元素宽高不等（7:3、8:5），而非 1:1

**注意**：非对称不是「摆歪」，是**用不平衡制造视觉权重**。重心仍须稳定，不能让人失去阅读起点。

## 改造循环纪律

| 规则 | 说明 |
|------|------|
| 上限 3 轮 | 超过 3 轮仍不达标 → 回退 G1（立场）或 G2（风格），不再磨视觉层 |
| 每轮只改命中项 | 不要顺手改没被诊断出的地方——会引入新的不一致 |
| 每轮后重跑脚本 | 确认分数下降；若上升，立即回退这一轮 |
| 保留改动记录 | 写进 `assets/templates/style-decision.md` 的改动摘要 |
| 误杀优先复核 | 若某轮改完「说不清哪里不对」，先查 `false-positives.md` |
