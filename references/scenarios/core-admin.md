# 场景处方 · 管理界面（核心）

> 中后台、CRUD 控制台、配置中心、审批流、数据管理

## 一、定位

**让操作者在成百上千条记录中，稳定、可预期、不易出错地完成批量工作。**

判据：**一致性 > 局部最优。** 管理的核心成本是学习成本与误操作成本，不是视觉惊喜。

---

## 二、使用者与情境

| 项 | 典型答案 |
|----|----------|
| 谁 | 运营、客服、管理员、内部员工；**高频重复使用** |
| 何时 | 工作日全天，单次会话长（1–8 小时） |
| 何地 | 桌面浏览器，1440–1920 宽 |
| 首要目标 | 准确完成增删改查与批量操作 |
| 次要目标 | 快速定位目标记录、可追溯变更 |

**区别于用户界面**：管理界面的使用者是「被迫使用者」——他们不在乎美感，在乎**速度和不出错**。

---

## 三、设计重心（五条，按优先级）

1. **可预期性优先。** 同一操作在所有页面表现一致；同样的图标永远同一个含义。
2. **减少点击距离。** 常见任务的操作路径 ≤2 步；避免多页跳转。
3. **错误必须可恢复。** 破坏性操作要么可撤销，要么二次确认；批量操作两者都要。
4. **状态可见。** 用户永远知道「正在加载 / 已保存 / 保存失败 / 有未保存改动」。
5. **一致 > 惊艳。** 不给任何单页加特例样式。

---

## 四、推荐风格与旋钮

| 首选 | 01 Swiss Minimalism / 05 Data-Dense Dashboard |
|------|---------------------------------------------|
| 次选 | 23 Fluent 2（桌面密度与层次） / 02 Flat Design |
| 符合既有系统 | 若项目已有组件库（antd / MUI），**沿用其设计语言**，只调 token |

```
--variance 3    （对称与稳定是要求；表单必须左右对齐）
--motion   2    （只保留状态反馈，无入场动画）
--density  7    （密集但留可读余量）
```

> **不要为了「独特」给管理界面加非对称布局。** 那是本场景最常见、代价最高的误杀。

## 五、关键规格

### 5.1 色彩

| 用途 | 规格 |
|------|------|
| 底色 | 中性（`#F5F5F5` 页面底 / `#FFFFFF` 容器底） |
| 主色 | **1 个**，用于主操作、链接、选中导航、焦点环 |
| 语义色 | 成功 / 警告 / 错误 / 信息，**只用于状态，不用于装饰** |
| 分类色 | 标签、图表可用预设色板，**不得用于主操作** |
| 强调色 | 每屏 1 个，且只给「本屏最重要的动作」 |

> **主按钮唯一**：同一决策区不得出现两个主色按钮。次要操作降为默认样式。

### 5.2 排版

| 元素 | 规格 |
|------|------|
| 正文基准 | **13–14px**（企业级用 14px 换信息密度，见下方说明） |
| 表头 | 同字号 + 字重 600 + 底色区分 |
| 表格正文 | 12–13px，行高 1.3–1.4 |
| 数字 | **`tabular-nums` + 右对齐 + 相同有效位数** |
| 字重 | **只用 400 + 600**（或 400/500/600）；禁用 100–300 与 700+ |

> **为什么基准可以小于 16px**：管理界面是**桌面高密度场景**，1440px 宽要容纳侧栏 + 表头 + 8 列数据 + 详情面板。14px 下正文行可达约 75 字符的扫视甜点区。
> ⚠️ 但这只适用于**桌面**。若管理界面需在移动端可用，移动端必须回到 16px。

### 5.3 布局与栅格

| 项 | 规格 |
|----|------|
| 间距基数 | **4px**，六档尺度：`4 / 8 / 16 / 24 / 32 / 48` |
| 栅格 | 24 列；Gutter 固定，Column 随宽伸缩 |
| 侧栏 | 240–280px（展开）/ 56–72px（收起） |
| 内容最大宽 | `1280–1440px` 后居中 |
| 三层表面 | 页面底 `#F5F5F5` → 容器 `#FFFFFF` → 浮层 `#FFFFFF` + 阴影 |
| 禁止 | 魔法数字间距（如 `13px`、`11px`） |

### 5.4 表格规格（本场景的核心组件）

| 项 | 规格 |
|----|------|
| 行高 | 紧凑 36–40px / 标准 48px |
| 表头 | 粘性，底色区分，排序指示器 `aria-sort` |
| 斑马纹 | **默认不用**；依赖 hover 行高亮强调当前行 |
| 空单元格 | 显示 `-`，**不留白** |
| 时间/状态/操作列 | **词语完整不折行** |
| 列宽 | 数字列窄，文本列弹性，操作列固定 |
| 分页 | 默认每页 10/20/50 可选；>5 页提供快速跳转 |
| 批量操作 | 全选 / 反选 / 已选计数；破坏性批量需二次确认 + 可撤销 |
| 长文本 | 优先换行；必须截断时用省略号 + Tooltip 给全文 |

### 5.5 表单规格

| 项 | 规格 |
|----|------|
| 标签位置 | **标签右对齐 + 冒号对齐**（推荐）或顶部对齐；全站统一 |
| 必填标记 | 明确标识（星号 + 说明） |
| 校验时机 | **onBlur**（不是 onKeyPress）；错误就近显示在字段下方 |
| 帮助文本 | 复杂字段提供**持久**帮助文本，不只靠 placeholder |
| 提交反馈 | loading → 成功/失败；失败保留用户输入 |
| 多错误 | 顶置可聚焦的错误摘要，每项链接到对应字段 + 保留行内错误 |
| 危险操作 | 语义危险色 + 视觉上与主操作分离 + 二次确认 + 可撤销 |
| 长表单 | 自动保存草稿；离开前提示未保存改动 |
| 只读 vs 禁用 | 必须视觉与语义上可区分 |

### 5.6 导航

| 项 | 规格 |
|----|------|
| 主导航 | 侧边栏（≥1024px）；移动端折叠为抽屉 |
| 层级 | 一级（侧栏）与二级（页签/内嵌）**清晰分离** |
| 当前态 | 必须高亮（底色 + 文字色 + 或左侧指示条） |
| 面包屑 | 层级 ≥3 时使用；**超过 5 级需折叠** |
| 返回行为 | 必须可预期，且**恢复滚动位置、筛选状态与输入** |
| 深链接 | 所有关键页可达 URL（含筛选与分页状态） |
| 禁止 | 用模态做主导航（会切断用户路径） |

### 5.7 反馈与状态

| 状态 | 规格 |
|------|------|
| 加载 | >1s 用骨架屏（非阻塞 spinner）；按钮异步时禁用 + spinner |
| 空状态 | 说明「为什么空」+ 具体下一步行动 |
| 错误 | 说清「原因 + 怎么修」+ 重试入口 |
| 成功 | 轻量 toast（3–5s 自动消失）+ 列表局部刷新 |
| 重要失败 | **不得只用 toast**（易漏）→ 用对话框或持久 Alert |
| 乐观更新 | 可撤销操作（如删除）用「立即生效 + 撤销 toast」，优于确认框 |

## 六、本场景的 AI 味与误杀

### 6.1 真正的 AI 味（要改）

| 症状 | 改造 |
|------|------|
| 每屏都是「标题 + 副标题 + 三等分统计卡 + 大表格」 | 按内容决定：统计卡只在真有 3 个并列指标时用；否则去掉 |
| 大圆角（16px+）+ 柔和阴影 + 彩色图标 | 控件圆角收到 6px 内，表面 8px；阴影收敛到 ≤2 档 |
| 主色用在所有可点的地方 | 主色只给每屏唯一主操作 |
| 卡片间距与内部间距相同，无层级 | 区块间距 ≥ 内部间距 ×3 |
| 每行都有彩色状态标签（Tag 满天飞） | 只有真正需要快速扫视的状态才给色；其余用文字 |
| 表格加了毫无用途的斑马纹 + 悬停抬升 + 渐变表头 | 保留 hover 行高亮即可 |
| 按钮文案是「提交 / 确定 / 了解更多」 | 改为结果导向：「保存并发布」/「删除这 12 条」 |

### 6.2 误杀（不许改）——**第二高风险场景**

| 会被误判 | 为什么不能改 |
|----------|-------------|
| 对称的表单布局（标签右对齐） | 对齐让眼球顺着冒号找到所有字段，**提升填写效率** |
| 14px 基准 / 12px 表格正文 | 桌面高密度场景的最优解 |
| 全站一致、无特例 | 一致性换来可预测性与低学习成本 |
| 大量的重复结构（每个列表页骨架相同） | 重复降低学习成本（设计原则之「重复」） |
| 系统字体栈 | 性能 + 平台原生感 |
| 单色 UI | 克制，色彩预算留给状态与数据 |
| 完整的状态设计（loading/empty/error/disabled） | 这是可用性必需，不是冗余 |
| 默认无斑马纹 | 依赖 hover 是刻意选择 |
| 侧边栏 + 顶部栏的经典布局 | 符合桌面习惯，不是「模板感」 |

> **判定口令**：**「改了之后，用户会不会更容易点错或找不到？」**
> 会 → 设计纪律，不许改。

## 七、检查清单

**一致性**
- [ ] 同一操作在所有页面表现一致（措辞、位置、图标）
- [ ] 无任何单页特例样式
- [ ] 图标全站同族同线宽，无 emoji
- [ ] 主按钮全站措辞统一

**效率**
- [ ] 常见任务操作路径 ≤2 步
- [ ] 列表支持排序 / 筛选 / 分页，且筛选状态进 URL
- [ ] 批量操作有全选/反选 + 已选计数
- [ ] 返回时恢复滚动位置与筛选状态

**防错**
- [ ] 破坏性操作有二次确认**且**可撤销
- [ ] 危险操作视觉上与主操作分离
- [ ] 表单 onBlur 校验，错误就近显示
- [ ] 多错误有顶置摘要 + 行内错误
- [ ] 未保存改动离开前有提示

**状态可见**
- [ ] loading / empty / error / disabled 四态齐全
- [ ] 重要失败不用 toast 单独承担
- [ ] 数字列 `tabular-nums` + 右对齐
- [ ] 空单元格显示 `-` 而非留白

**无障碍**
- [ ] 键盘可完成全部操作，无键盘陷阱
- [ ] 焦点环可见，顺序与视觉顺序一致
- [ ] 表格排序有 `aria-sort`
- [ ] 表单错误用 `aria-live` 或 `role="alert"`
- [ ] 对比度：正文 ≥4.5:1，UI 边界 ≥3:1
