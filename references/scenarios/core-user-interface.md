# 场景处方 · 用户界面（核心）

> C 端产品页、工具型 Web App、SaaS 前台、面向外部用户的功能界面

## 一、定位

**让用户在第一次使用时就知道该做什么，在第十次使用时依然觉得顺手。**

判据：**首次任务完成率** 与 **重复使用效率**，两者都要，且常冲突——解决冲突正是本场景的设计内容。

---

## 二、使用者与情境

| 项 | 典型答案 |
|----|----------|
| 谁 | 外部用户、客户、非受训人员；**自愿使用者** |
| 何时 | 碎片化、可能被打断 |
| 何地 | 桌面 + 移动混合；网络条件不一 |
| 首要目标 | 完成自己的任务，不是「学会这个软件」 |
| 次要目标 | 建立信任、理解产品边界 |

**区别于管理界面**：用户界面可以（也应该）有品牌辨识度——因为**用户会选**，而管理员不会。

---

## 三、设计重心（五条，按优先级）

1. **一眼知道下一步。** 每屏只有一个主行动，且它必须比别的元素明显。
2. **首次可用，进阶可深。** 核心功能零学习成本；高级能力渐进披露。
3. **信任来自可验证的信息。** 具体数字、真实截图、明确边界与代价。
4. **允许品牌表达。** 这是本场景与管理界面的最大区别——**要有立场**。
5. **脆弱场景要兜住。** 弱网、空数据、错误、误操作，都必须有优雅出口。

---

## 四、推荐风格与旋钮

| 首选 | 01 Swiss Minimalism（工具型） / 09 Glassmorphism（SaaS 型） / 22 Material 3 Expressive（移动优先） |
|------|------------------------|
| 次选 | 23 Fluent 2 / 10 Liquid Glass / 03 Bento Box Grid |
| 需强辨识度 | 17 Brutalism / 13 Claymorphism（视受众） |

```
--variance 5    （平衡；可有 1–2 处非对称）
--motion   4    （状态反馈 + 轻度入场，克制）
--density  5    （标准）
```

> **本场景允许更多品牌表达，但「差异化抓手」仍只能有 1 个。** 用户界面的 AI 味往往来自「哪里都想表达」。

---

## 五、关键规格

### 5.1 色彩与品牌

| 项 | 规格 |
|----|------|
| 主色 | 1 个，承载品牌；用于主操作与关键链接 |
| 强调色 | 1 个，用于「唯一需要被注意」的地方（可等于主色） |
| 中性色 | 4 档（主文字/次文字/三级说明/占位禁用） |
| 功能色 | 成功/警告/错误/信息，仅状态 |
| 色相总数 | ≤3（不含中性灰） |

**「有立场」自检**：把这套配色换到别人的产品上，会显得不对吗？会 → 有立场。

### 5.2 排版

| 元素 | 规格 |
|------|------|
| 正文 | **16px**（移动端必须；避免 iOS 自动缩放） |
| 行高 | 1.5–1.75 |
| 行宽 | 移动 35–60 字符；桌面 60–75 字符 |
| 字号档 | ≥5 档，**最大/最小 ≥3.5×** |
| 字重 | 400 / 500 / 600 三档 |
| 大标题 | 收紧字距；行高 1.15–1.25 |

### 5.3 布局

| 项 | 规格 |
|----|------|
| 断点 | 375 / 768 / 1024 / 1440（系统化，不用随机值） |
| 移动优先 | 先做移动，再加响应式变体 |
| 容器宽 | 桌面 `max-width` 1200–1440，居中 |
| 间距尺度 | 4/8 基数；区块间距 ≥ 内部间距 ×3 |
| 纵向节奏 | 分组内 8/12 · 分组间 32/48 · 章节间 64/96 |
| 非对称 | 至少 3 处（跨列/偏移/尺寸对比） |

### 5.4 导航

| 项 | 规格 |
|----|------|
| 顶部导航 | 一级类目 2–7 个；标题 4–15 字符（中文 2–6） |
| 底部导航 | 移动端 ≤5 项，**图标 + 文字**（纯图标伤害可发现性） |
| 当前态 | 必须高亮 |
| 搜索 | 易达（顶栏或 Tab），并提供最近/建议 |
| 面包屑 | ≥3 级时使用 |
| 返回 | 可预期，且恢复滚动与输入状态 |

### 5.5 交互与反馈

| 项 | 规格 |
|----|------|
| 触控目标 | ≥44×44pt（iOS）/ ≥48×48dp（Android）；间距 ≥8px |
| 按压反馈 | ≤100ms 内可见；不改变布局边界 |
| 加载 | >1s 用骨架屏 / shimmer（非长期阻塞 spinner） |
| 空状态 | 「为什么空」+ 具体下一步 |
| 错误 | 「原因 + 怎么修」+ 重试 |
| 破坏性 | 二次确认 + 可撤销，或「立即执行 + 撤销 toast」 |
| 渐进披露 | 高级选项默认收起，不一次铺满 |
| 减少输入 | 记住上次选择、提供默认值、支持自动填充 |

### 5.6 信任建立（本场景特有）

| 手段 | 说明 |
|------|------|
| 具体数字 | 「已服务 1,240 个团队」>「广受信赖」 |
| 真实界面截图 | 优于插画 |
| 明确边界 | **主动写清不支持的场景**——这是最强的可信信号 |
| 透明的代价 | 「首月免费，之后 ¥99/月」而非「免费开始」 |
| 可撤销/可导出 | 降低试用门槛 |

## 六、本场景的 AI 味与误杀

### 6.1 真正的 AI 味（要改）

| 症状 | 改造 |
|------|------|
| Hero 居中 + 副标题居中 + 双按钮居中 + 紫蓝渐变背景 | 改偏置布局（左文右图），删除渐变 |
| 三等分特性卡（图标 + 标题 + 两行描述）× 6 | 收敛到 3 个真实差异点，或改为对照表 |
| 空心文案（Seamlessly / Empower / All-in-one） | 换具体事实，见 `../anti-ai/copy-tells.md` |
| 每张卡都圆角 20px + 柔和阴影 + hover 抬升 | 圆角收到 8–12px；阴影 ≤1 档；只让可点击卡抬升 |
| 图标用 emoji | 换同族 SVG |
| 动效均匀铺满全页 | 每屏 ≤2 个动画元素 |
| 通用积极收尾（开启你的旅程） | 换成具体下一步动作 |
| 「信任我们，安全可靠」类空话 | 写具体做法与可验证指标 |

### 6.2 误杀（不许改）

| 会被误判 | 为什么不能改 |
|----------|-------------|
| 16px 正文、宽松行高 | 可读性底线 |
| 移动端单列纵向流 | 拇指可达与阅读习惯要求 |
| 大面积留白 | 聚焦，不是浪费 |
| 只有一个 CTA | 聚焦是刻意的 |
| 无装饰插图 | 内容优先，不是缺失 |
| 完整的空/错/加载态 | 可用性必需 |
| 系统字体栈 | 性能与原生感 |
| 深链接与可分享 URL | 功能必需 |

> **判定口令**：**「改了之后，第一次来的用户会不会更不知道点哪？」**

## 七、检查清单

**聚焦与层次**
- [ ] 每屏只有一个主行动，且视觉上最明显
- [ ] 字号最大/最小比 ≥3.5×
- [ ] 差异化抓手只有 1 个
- [ ] 非对称结构 ≥3 处

**品牌与辨识度**
- [ ] 色相 ≤3，主色 + 强调色各 1
- [ ] 配色替换到竞品上会显得不对（有立场）
- [ ] 无紫粉渐变 / 无装饰性渐变
- [ ] 无 emoji 当图标

**可用性**
- [ ] 触控目标 ≥44pt，间距 ≥8px
- [ ] 按压反馈 ≤100ms 且不引起布局位移
- [ ] 空 / 加载 / 错误 / 禁用四态齐全
- [ ] 破坏性操作可撤销或二次确认
- [ ] 弱网有降级，离线有提示

**无障碍**
- [ ] 正文 ≥16px；对比 ≥4.5:1（大字 ≥3:1）
- [ ] 键盘可完成主流程，焦点可见且顺序合理
- [ ] 语义化标签（单一 h1、标题有序、landmark）
- [ ] 支持 `prefers-reduced-motion` 与动态字号
- [ ] 颜色不是唯一指示手段

**响应式**
- [ ] 375 / 768 / 1024 / 1440 四档验证
- [ ] 无横向滚动
- [ ] 固定元素为内容预留安全内边距
- [ ] 横屏可用
