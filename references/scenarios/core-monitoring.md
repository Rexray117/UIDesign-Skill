# 场景处方 · 企业监控界面（核心）

> 运维大屏、实时监控、告警中心、IoT 看板、设备状态台

## 一、定位

**让值班人员在最短时间内发现「哪一台出了问题」。**

判据：如果一个设计决策让人**多花 1 秒**才发现异常，这个决策就是错的——不管它多好看。

---

## 二、使用者与情境

| 项 | 典型答案 |
|----|----------|
| 谁 | 运维工程师、值班员、SRE |
| 何时 | **长时间盯屏**（夜班常见）、告警突发时 |
| 何地 | 大屏（远距离）/ 多显示器工作站（近距离） |
| 首要目标 | 异常发现速度 |
| 次要目标 | 定位根因、确认处置进度 |

**关键情境差异**：
- 大屏投放 → 距离 3–8 米，字号与对比要求显著提高
- 工作站 → 需要高密度与多窗口共存

---

## 三、设计重心（五条，按优先级）

1. **异常必须最先被看到。** 正常态要「安静」，异常态要「打断」。这是唯一的硬约束。
2. **信息密度是特征，不是缺陷。** 值班员需要一屏看完，滚动等于漏看。
3. **UI 保持中性，色彩留给数据。** 界面本身不做视觉主张，色彩只用于状态编码。
4. **稳定的空间位置。** 同一指标永远在同一位置——值班员靠肌肉记忆扫视，位置变化会造成漏检。
5. **无装饰动效。** 任何装饰动画都会与告警争夺注意力。

---

## 四、推荐风格与旋钮

| 首选 | 05 Data-Dense Dashboard |
|------|------------------------|
| 次选 | 06 Dark Mode (OLED) / 08 HUD Sci-Fi FUI / 07 Terminal CLI |
| 骨架可用 | 02 Flat Design（做框架），数据区转 05 |

```
--variance 3    （稳定 > 新颖，空间位置必须可预期）
--motion   2    （仅数据更新与告警脉冲，无装饰动画）
--density  9    （密集，一屏看完）
```

> ⚠️ `--motion` 高于 4 时，必须证明每个动效都在编码信息而非装饰。

## 五、关键规格

### 5.1 色彩

| 用途 | 规格 |
|------|------|
| 界面底色 | 中性深色（`#0B0E14`–`#121212`）或中性浅灰；**不用彩色底** |
| 文字 | 4 档灰度，对比 ≥7:1（大屏）/ ≥4.5:1（工作站） |
| 状态色 | **严格语义化，全站唯一映射**：正常绿 / 警告琥珀 / 严重红 / 未知灰 |
| 强调色 | **0 个**。强调的职责由状态色承担 |
| 禁止 | 紫粉渐变、装饰渐变、同屏 >4 个色相 |

> **色盲安全**：状态色**必须**配图标或形状（`●` 正常 / `▲` 警告 / `■` 严重）。仅靠红绿是失败设计。

### 5.2 排版

| 元素 | 规格 |
|------|------|
| 关键指标数字 | **36–72px，等宽，`tabular-nums`，字重 600** |
| 指标标签 | 11–12px，字距放开（`+0.05em`），可用全大写 |
| 表格正文 | 12–13px，行高 1.3 |
| 日志正文 | 12–13px 等宽 |
| 最小字号 | **不得低于 11px**（大屏不得低于 16px） |

**层次靠**：字号对比（4× 以上）+ 明度 + 字重，**不靠颜色**。

### 5.3 布局与密度

| 项 | 规格 |
|----|------|
| 间距基数 | 4px；组件内 4–8，区块间 16–24 |
| 栅格 | 12 或 24 列；状态总览区跨满 |
| 首屏结构 | ① 全局状态条 ② 告警列表（唯一主卡） ③ 关键指标网格 ④ 趋势图 ⑤ 明细表 |
| 主卡判定 | **告警区必须是视觉上唯一的主卡**（跨列 / 更大字号 / 唯一高对比） |

### 5.4 状态与反馈

| 状态 | 表现 |
|------|------|
| 正常 | 低对比、无动效、静默 |
| 警告 | 琥珀 + 图标 + 轻微脉冲（≤1.5s 周期，可关） |
| 严重 | 红 + 图标 + **一次显著打断**（顶部横幅或声音，可配置） |
| 未知 / 无数据 | 灰 + 明确文字（**不得留空**——空白无法与「正常」区分） |
| 数据陈旧 | 必须显示「最后更新 x 秒前」，超过阈值变色 |

> **无数据 ≠ 正常。** 这是监控界面最常见的严重缺陷。

### 5.5 刷新与实时

- 数值更新**不得**引起布局位移（用 `tabular-nums` 固定宽度）
- 更新频率 >1s 的数字不做逐帧动画
- 提供暂停/冻结开关（值班员需要定格分析）
- 时间显示必须明确时区

## 六、本场景的 AI 味与误杀

### 6.1 真正的 AI 味（要改）

| 症状 | 改造 |
|------|------|
| 「卡片 + 大圆角 + 柔和阴影 + 渐变色块」的传统看板模板 | 拆掉阴影与圆角，改为**边框分隔 + 中性底 + 等宽数字** |
| 指标卡一律等大等重，无主次 | 让**告警区跨列且字号跳档** |
| 装饰性图表动画（渐入、增长） | 删除，改为数据更新时才动 |
| 每个指标配一个彩色圆环图 | 数字 + 迷你趋势线，色彩只编码状态 |
| 紫蓝渐变背景 | 换中性深色 |
| 空白处填装饰图形/插画 | 删除，留白或放次级信息 |

### 6.2 误杀（不许改）——**本场景误杀风险最高**

| 会被误判为 AI 味的特征 | 为什么不能改 |
|----------------------|-------------|
| 高信息密度 | 这是产品的核心价值。改宽松 = 让人滚动 = 增加漏检 |
| 小字号（12–13px） | 工作站距离下的最优解。放大 = 一屏放不下 |
| 深色主题 | 夜班场景的标准选择，不是「暗色换皮」 |
| 居中指标卡 | 数字居中便于扫视比对，是正确解 |
| 低饱和、单调 UI | **UI 中性是刻意的**——色彩预算留给数据 |
| 对称网格 | 空间位置稳定是要求，不是惰性 |
| 表格斑马纹（若已用） | 密集行的可读性手段 |
| 无 hover 抬升 | 大屏场景本就无指针 |
| 一致的重复结构 | 一致性换来扫视速度 |

> **判定口令**：**「改了之后，值班员会不会更容易漏掉告警？」**
> 会 → 这是设计纪律，不许改。

## 七、检查清单

**异常可发现性**
- [ ] 告警区是视觉上唯一的主卡（跨列或字号跳档）
- [ ] 正常态足够「安静」（低对比、无动效）
- [ ] 严重状态有一次显著的打断（横幅/声音）
- [ ] 无数据态有明确文字，未被留空
- [ ] 数据陈旧有「最后更新」提示与变色

**可读性**
- [ ] 关键数字等宽 + `tabular-nums` + ≥36px
- [ ] 最小字号 ≥11px（大屏 ≥16px）
- [ ] 灰度 ≥4 档且层级分明
- [ ] 对比度 ≥7:1（大屏）/ ≥4.5:1（工作站）

**色彩纪律**
- [ ] UI 保持中性，无装饰渐变
- [ ] 状态色全站唯一映射
- [ ] 状态色配图标/形状（色盲安全）
- [ ] 同屏色相 ≤4

**稳定性**
- [ ] 同一指标位置固定，不随数据变化移动
- [ ] 数值更新不引起布局位移
- [ ] 提供暂停/冻结
- [ ] 时间显示明确时区

**无障碍**
- [ ] 键盘可遍历所有可交互元素
- [ ] 焦点环可见（即使在暗色 + 密集环境下）
- [ ] 支持 `prefers-reduced-motion`（告警脉冲降级为静态高对比）
- [ ] 无仅靠颜色传递的状态
