# 组件规范与六态矩阵

---

## 一、六态是底线

任何可交互元素**必须**具备六态。缺任一即为可用性缺陷——**与 AI 味无关，不许砍**。

| 状态 | 触发 | 视觉变化 | 优先级 |
|------|------|----------|:------:|
| default | 无 | 基础外观 | 6 |
| hover | 指针悬停 | 轻微色移 | 5 |
| focus | Tab / 点击 | 焦点环 | 4 |
| active | 按下 | 最深色 | 3 |
| loading | 异步动作 | 指示器 + 降透明度 | 2 |
| disabled | disabled 属性 | 降低不透明度 | 1 |

**优先级（高 → 低）**：`disabled > loading > active > focus > hover > default`
多状态并存时按此覆盖。

### 状态实现纪律

| 纪律 | 说明 |
|------|------|
| **按下态不改变布局边界** | 用颜色/透明度/层级，不用位移 → 否则引起抖动 |
| **焦点环必须可见且高对比** | 环宽 2px、偏移 2px、环色高对比；**不得为了「干净」而移除** |
| **禁用态语义化** | 用原生 `disabled`；视觉降透明度 0.5 + `cursor: not-allowed`；**不得看起来可点却无响应** |
| **loading 不阻塞输入** | 动画期间 UI 保持可交互（除正在提交的元素） |
| **只读 ≠ 禁用** | 只读与禁用必须视觉与语义上都可区分 |

## 二、状态矩阵（用 token 表达）

| 属性 | Default | Hover | Active | Disabled |
|------|---------|-------|--------|----------|
| 背景 | `--color-primary` | `--color-primary-hover` | 更深一档 | muted |
| 文字 | `--color-primary-foreground` | 同 | 同 | `--color-text-disabled` |
| 边框 | none | none | none | `--color-border` |
| 阴影 | raised | card | none | none |

## 三、焦点环规格

```css
.focusable:focus-visible {
  outline: none;
  box-shadow:
    0 0 0 var(--ring-offset) var(--color-background),
    0 0 0 calc(var(--ring-offset) + var(--ring-width)) var(--color-ring);
}
```

| 属性 | 值 |
|------|-----|
| 环宽 | 2px（高对比场景 3–4px） |
| 环偏移 | 2px |
| 环色 | 主色或高对比色 |
| 偏移色 | 背景色（制造「间隙」感） |

**附加纪律**：
- 用 `:focus-visible` 而非 `:focus`（避免鼠标点击也显示环）
- **粘性元素与浮层不得遮挡焦点**（`scroll-margin` / `scroll-padding`）
- 焦点顺序必须与视觉顺序一致
- 不得设置 `outline: none` 而不提供替代环

## 四、变体实现（变量覆写）

**唯一推荐方式**：组件只消费 `--component-*`，变体只覆写变量。

```css
.button        { --btn-h: 40px; --btn-px: var(--space-4); --btn-fs: var(--font-size-sm); }
.button.sm     { --btn-h: 32px; --btn-px: var(--space-3); --btn-fs: var(--font-size-xs); }
.button.lg     { --btn-h: 48px; --btn-px: var(--space-6); --btn-fs: var(--font-size-base); }

.button {
  height: var(--btn-h);
  padding-inline: var(--btn-px);
  font-size: var(--btn-fs);
  background: var(--btn-bg, var(--color-primary));
  color: var(--btn-fg, #fff);
  border-radius: var(--button-radius);
}
```

**为什么这样最好**：不写重复 CSS、变体正交组合、新增变体不动主样式。

## 五、组件规范要点

### 5.1 按钮

| 项 | 规格 |
|----|------|
| 高度 | 32 / 40 / 48px（走尺度，非随意值） |
| 圆角 | 控件档（≤表面档） |
| 主按钮 | **每屏 / 每个决策区只有 1 个** |
| 次要按钮 | 视觉明显降级（描边 / 文字按钮） |
| 危险按钮 | 语义危险色 + **与主操作视觉分离** |
| 图标按钮 | 必须有 `aria-label`；触控热区 ≥44pt |
| 加载态 | 禁用 + 指示器，宽度不变（防抖动） |

**按钮文案纪律**：动词开头，说结果。
「保存并发布」优于「提交」；「删除这 12 条」优于「确定」；「看 3 分钟演示」优于「了解更多」。

### 5.2 输入框 / 表单

| 项 | 规格 |
|----|------|
| 高度 | ≥32px（桌面）；移动端 ≥44px |
| 标签 | **必须可见**（不用 placeholder 当标签） |
| 帮助文本 | 复杂字段提供**持久**帮助文本 |
| 校验时机 | **onBlur**（不是 `onKeyPress`） |
| 错误 | 就近显示 + `aria-describedby` 关联 + `aria-invalid` |
| 多错误 | 顶置可聚焦错误摘要，每项链接到字段；**保留行内错误** |
| 必填 | 明确标识 |
| 密码 | 提供显示/隐藏 |
| 自动填充 | 支持 `autocomplete` / `textContentType` |
| 只读 vs 禁用 | 视觉与语义都要可区分 |
| 破坏性 | 危险色 + 二次确认 + 可撤销 |

### 5.3 容器：卡片 / 模态 / 抽屉

| 组件 | 规格 |
|------|------|
| 卡片 | 表面档圆角；内边距 16–24px；**阴影仅必要时加**；嵌套控件保持统一间距 |
| 模态 | 与卡片同面同圆角，靠阴影区分；遮罩实测前景可读性；内边距 20–24px |
| 模态动效 | **从触发源出发**（scale + fade 或 slide-in） |
| 模态出口 | 必须有明确关闭；移动端支持下滑关闭；**打开时焦点移入，关闭后焦点归还触发元素** |
| 抽屉 | 只用于次级导航或详情，**不放主要动作** |
| 层级 | 表面 ≤3 层 |

### 5.4 导航组件

| 组件 | 规格 |
|------|------|
| 顶部导航 | 一级类目 2–7 项；标题 4–15 字符（中文 2–6） |
| 侧边导航 | 无限层级（可配滚动）；适合信息层级多、切换频繁的管理场景 |
| 底部导航（移动） | **≤5 项，图标 + 文字**；只用于顶层，不得嵌套子导航 |
| 页签 | 分类标题 2–6 中文字；激活态可用下划线/指示条；**企业级可不用背景填充** |
| 面包屑 | 层级 ≥3 时使用；显示 ≤3 级，超过需折叠，**最多不超过 5 级** |
| 步骤条 | 多于 2 步时使用，**建议 ≤5 步**；每阶段文字 ≤12 字符 |
| 分页 | >5 页提供快速跳转；支持自定义每页行数 |
| 当前态 | **必须高亮**（颜色 / 字重 / 指示条） |
| 禁止 | 同一层级混用 Tab + 侧栏 + 底部导航；用模态做主导航 |

### 5.5 表格

| 项 | 规格 |
|----|------|
| 表头 | 底色区分 + 字重 600 + 粘性；排序指示 `aria-sort` |
| 行高 | 紧凑 36–40px / 标准 48px |
| 斑马纹 | **默认不用**；靠 hover 行高亮 |
| 对齐 | 文字左对齐；**数字右对齐 + 等宽 + 相同有效位数** |
| 空单元格 | 显示 `-`，**不留白** |
| 时间/状态/操作列 | 词语完整不折行 |
| 长文本 | 优先换行；必须截断时省略号 + Tooltip 给全文 |
| 空数据 | 有明确空状态（说明为什么空 + 下一步） |
| 加载 | 骨架屏，**不显示空表头** |
| 无障碍 | 提供表格替代与 `aria-sort`；详细数据下钻 |

### 5.6 反馈组件

| 组件 | 使用场景 | 纪律 |
|------|----------|------|
| Alert | 非阻断的静态提示 | 优先顶部；不自动消失；状态靠图标 + 色调，**不靠低对比彩色正文** |
| Message / Toast | 轻量结果反馈 | 3–5s 自动消失；**不抢焦点**；`aria-live="polite"` |
| Notification | 系统主动推送的全局信息 | 右上角 |
| Badge | 聚合提示 | 重要用数字；次要可用红点；**关键状态不用 Badge 承担** |
| Tooltip | 精确描述指向对象 | 高对比反向表面；**由框架定位**；可键盘触达 |
| Popover | 承载更复杂内容 | 可含链接与按钮（区别于 Tooltip） |
| Popconfirm | 目标元素附近的轻量确认 | 比全屏模态更轻 |
| Dialog | 重要反馈 / 关键确认 | **弹窗是很强的机制**——只用于非常重要且可操作的信息 |
| Skeleton | >1s 的加载 | 优于长期阻塞 spinner |

> **重要失败信息不得只用 toast** —— 展示时长太短（默认 3s），易漏。改用对话框或持久 Alert。

### 5.7 数据展示

| 组件 | 纪律 |
|------|------|
| 折叠面板 | 关联度低时可用「手风琴」（只允许单项展开） |
| 卡片列表 | 通常按栅格排列，**一行不超过 4 个**；空间有限时可截断 |
| 轮播 | 数量 **3–5 个**为最佳；必须提供暂停且聚焦时停止 |
| 树形 | 用于层级信息；用户可同时浏览多层 |
| 时间轴 | 垂直展示时间流，一般倒序 |

## 六、图标

| 纪律 | 说明 |
|------|------|
| **禁止 emoji 当图标** | emoji 依赖字体、跨平台不一致、无法被 token 控制 |
| 只用矢量 | SVG 或平台矢量图标，可缩放、可换肤、支持主题 |
| 同一图标族 | 同一产品的线宽与圆角风格必须统一 |
| 尺寸走 token | `icon-sm` / `icon-md`(24px) / `icon-lg`，**不随机取 20/24/28** |
| 线宽一致 | 同一层级内线宽一致（如统一 1.5px 或 2px） |
| 填充/描边纪律 | 同一层级只用一种（不混用实心与描边） |
| 语义由用法决定 | 装饰性图标（旁边有可见文字）→ 对无障碍树隐藏；有意义图标 → 给文本替代；图标控件 → 给可访问名称并播报状态 |
| 对比度 | 有语义的图标 ≥3:1；**装饰性图标不得承载信息** |
| 品牌 Logo | 用官方资产，遵守留白与配色规范，**不重绘、不调色** |

> 105 个精选图标（含语义角色与适用上下文）见 `data/icons.csv`。

## 七、组件自检

- [ ] 每个可交互元素都有六态
- [ ] 按下态不引起布局位移
- [ ] 焦点环可见、高对比、`focus-visible`
- [ ] 粘性元素与浮层不遮挡焦点
- [ ] 禁用态语义化（原生属性 + 视觉）
- [ ] 只读与禁用可区分
- [ ] 变体用变量覆写实现，无重复 CSS
- [ ] 主按钮每屏唯一
- [ ] 危险操作有二次确认或可撤销
- [ ] 按钮文案说结果
- [ ] 表单有可见标签 + 持久帮助文本 + onBlur 校验
- [ ] 多错误有顶置摘要 + 行内错误
- [ ] 模态焦点管理与归还正确
- [ ] 表格数字右对齐 + 等宽；空单元格用 `-`
- [ ] 重要失败不用 toast 单独承担
- [ ] 图标全站同族同线宽，无 emoji
- [ ] 装饰性图标对无障碍树隐藏
- [ ] 触控热区 ≥44pt（图标小于该值时已扩展）
