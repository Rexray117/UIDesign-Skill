# 动效规范

> **核心命题**：动效必须**表达因果关系**，不做装饰。
> 一条判据贯穿全文：**这个动效删掉之后，用户会失去什么信息？** 答不出 → 删。

---

## 一、动效的四个正当价值

| 价值 | 说明 |
|------|------|
| 增加认知舒适度 | 让状态转换显得「成立」 |
| 描述层级与空间关系 | 元素从哪来、到哪去 |
| 提供反馈、明确意图 | 用户知道操作被接收了 |
| 引导注意力 | 只在真正需要时 |

**反面**：为了「有活力」「高级感」而加动效 → 装饰过载（D3）。

---

## 二、时长尺度

### 2.1 三档基础时长

```css
--duration-fast:   100ms;  /* 状态变化：hover / focus / press */
--duration-normal: 150ms;  /* 组件内部转场：折叠、淡入淡出 */
--duration-slow:   300ms;  /* 表面级变化：模态进入、抽屉滑入 */
```

### 2.2 按转场类型

| 转场 | 时长 | 缓动 |
|------|:----:|------|
| 颜色 / 背景 | 150ms | `ease-in-out` |
| 不透明度 | 150ms | `ease` |
| 变换（transform） | 200ms | `ease-out` |
| 阴影 | 200ms | `ease-out` |
| 模态进入 | 300ms | `ease-out` |
| 抽屉滑入 | 300ms | `ease-out` |
| 页面转场 | 250–350ms | `ease-in-out` |

### 2.3 缓动原则

| 情形 | 缓动 |
|------|------|
| 到达（进入、出现） | **减速**（decelerate） |
| 离开（退出、消失） | **加速**（accelerate） |
| 恒定速率（进度条、旋转） | 线性 |

**首选弹簧/物理曲线**，优于线性或固定的 cubic-bezier。
**不要为每个转场随意挑缓动**——若没有匹配的，统一用 `ease-in-out` 然后继续。

## 三、八条硬性规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | **只用 `transform` 与 `opacity`** | **禁止**动画 `width` / `height` / `top` / `left`（触发重排） |
| 2 | **出场快于入场** | 出场 ≈ 入场的 **60–70%**。出场不需吸引注意力，简单消失即可 |
| 3 | **每屏动画元素 ≤1–2 个** | 超过就是过载 |
| 4 | **错峰序列 30–50ms** | 列表/网格入场逐项延迟；禁止全部同时或过慢 |
| 5 | **必须可中断** | 用户点击/手势**立即取消**进行中的动画 |
| 6 | **不阻塞输入** | 动画期间 UI 保持可交互 |
| 7 | **支持 `prefers-reduced-motion`** | 必须；降级为静态或仅保留不透明度变化 |
| 8 | **不引起布局位移** | 动画不得导致 reflow 或 CLS；位置变化用 `transform` |

---

## 四、微交互规格

| 交互 | 规格 |
|------|------|
| **按下反馈** | **≤100ms** 内可见；缩放 0.95–1.05，松开复位；不改变布局边界 |
| **悬停** | 150ms；轻微色移或层级变化；**不引起位移** |
| **触感反馈** | 仅用于确认与重要操作；**不过度使用** |
| 拖拽 / 滑动 / 捏合 | 必须实时跟随手指（无延迟感） |
| 输入延迟 | 点击/滚动反馈 **<100ms** |
| 悬停抬升 | **只给可点击卡片**；静态信息卡不响应 |

---

## 五、加载与等待

| 等待时长 | 处理 |
|----------|------|
| <300ms | 无需指示（闪烁更糟） |
| 300ms–1s | 轻量指示器（按钮内 spinner） |
| >1s | **骨架屏 / shimmer**（优于长期阻塞 spinner） |
| >10s | 进度条 + **取消操作** |
| 超时 | 明确超时提示 + 重试入口 |

**纪律**：
- **不用全屏阻塞 spinner 应付长时间等待**
- 骨架屏的尺寸必须与真实内容一致（否则加载完成时布局跳动）
- 数据加载失败 → 显示错误 + 重试，**不留空图表**

---

## 六、空间连续性与方向

| 规则 | 说明 |
|------|------|
| **模态 / 抽屉从触发源出发** | scale + fade 或从触发按钮方向 slide-in |
| **页面转场保持空间连续** | 共享元素 / 定向滑动 |
| **方向一致** | 前进向左/上；后退向右/下；**不得方向矛盾** |
| **共享元素转场** | 跨屏的同元素做 hero 转场，视觉连续 |
| 同容器内内容替换 | 用交叉淡入淡出（crossfade） |
| 视差 | 克制使用；必须尊重 reduced-motion 且不引起眩晕 |
| 淡出阈值 | **不透明度不低于 0.2** 时要么完全淡出，要么保持可见；不要停在半透明 |

---

## 七、自动播放与轮播

| 项 | 规格 |
|----|------|
| 数量 | 3–5 个为最佳 |
| 控件 | **必须**提供暂停/停止 |
| 聚焦 | 获得焦点时停止 |
| reduced-motion | 开启时停止自动播放 |
| 暗示 | 提供方向与数量的视觉暗示 |
| 无障碍 | 轮播内容对屏幕阅读器可控（不抢焦点） |

---

## 八、状态转移的健壮性

**最关键的一条工程规则**：

> **快速的状态变化必须安全地取消/替换先前的微交互，显式设置新的最终状态，且绝不能把正确性依赖于「动画结束事件」。**

原因：动画可能被打断、被浏览器节流、在后台标签页暂停。若逻辑挂在 `animationend` 上，用户快速操作就会导致状态错乱。

**正确做法**：动画只是视觉表现；**状态由代码显式管理**。

---

## 九、动效自检

**必要性**
- [ ] 每个动效都能说出「删掉会失去什么信息」
- [ ] 每屏动画元素 ≤2 个
- [ ] 无装饰性动画

**技术**
- [ ] 只用 `transform` / `opacity`
- [ ] 无动画 `width`/`height`/`top`/`left`
- [ ] 出场 ≈ 入场 60–70%
- [ ] 缓动符合「进减速、出加速」
- [ ] 错峰 30–50ms
- [ ] 动画期间可交互
- [ ] 动画可被用户操作中断
- [ ] 状态正确性不依赖动画结束事件
- [ ] 不引起 reflow 或 CLS

**无障碍**
- [ ] 支持 `prefers-reduced-motion`（降级为静态）
- [ ] 无导致眩晕的视差/缩放
- [ ] 自动轮播可暂停，聚焦时停止
- [ ] 无闪烁（>3 次/秒的闪烁禁止）

**反馈**
- [ ] 按压反馈 ≤100ms
- [ ] 按下态不改变布局边界
- [ ] >1s 的加载用骨架屏且尺寸匹配
- [ ] >10s 提供进度与取消
- [ ] 方向逻辑一致（前进/后退）
- [ ] 模态从触发源出发
